# **Leyenda:**

1. **ID:** Identificador único para cada historia de usuario (ej. 1.1, donde el primer número es la épica).  
2. **Historia / Descripción:** Redactada bajo el formato estándar: *Como \[rol\], quiero \[acción\], para \[beneficio\]*.  
3. **Criterio de Aceptación:** Condiciones específicas que deben cumplirse para marcar la historia como terminada.  
4. **Prioridad (MoSCoW):** Clasifica la importancia de la historia dentro del alcance del proyecto utilizando las categorías *Must* (obligatorio/MVP), *Should* (importante), *Could* (deseable) y *Won't* (fuera de alcance actual).   
5. **Estimación:** Valor cualitativo del esfuerzo y nivel técnico relativo necesario para implementar la historia de usuario (Baja, Media, Alta).   
6. **Estado:** Señala la fase o situación actual de la historia en el flujo de trabajo del proyecto (ej. *Por hacer*, *En proceso*, *Hecho*). Una historia pasa a *Hecho* solo si cumple todos sus criterios de aceptación; si queda algún criterio pendiente, permanece en *En proceso*.
